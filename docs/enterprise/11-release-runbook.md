# 11 — Release runbook (M11)

**Status: authoritative for v0.2.0.** The release ships **unsigned, sha256-checksummed**
(M11 plan ruling ①, 2026-11-11) — the checksum travels beside the artifact
(`<artifact>.sha256`; `shasum -a 256 -c` / PowerShell `Get-FileHash` to verify before
install). Cert purchase (Windows Authenticode, Apple Developer ID) is a future dated
ruling, not this release; the macOS pack script's `IRONFLEET_CODESIGN_ID` /
`IRONFLEET_NOTARY_PROFILE` env hooks carry signing when the owner buys the certs.

## 1. Release checklist (every release)

1. **Version + CHANGELOG** — `pyproject.toml`/`src/harness/__init__.py` stay
   single-sourced at the release version (test-enforced since M11 T1); CHANGELOG.md's
   top entry covers the version.
2. **Acceptance** — `scripts/accept_m11.py` (C1–C7) exit 0: C1 migration, C2 drill,
   C3 crashlog + no-telemetry, C4 packaging, C5 docs + DRAFT markers, C6 Linux
   installer contract, C7 versioning. The fresh-OS legs exit **2** (due-for-owner)
   until the owner's three fresh-OS records exist
   (data/eval/M11-FRESHOS/{windows,linux,macos}/RECORD.md).
3. **Pack + checksum** — `scripts/pack_windows.py` →
   `dist/IronFleet-harness-<version>-windows.zip` + `<zip>.sha256`. (The name keeps
   `-windows` only for accept_r2's fresh-machine contract; the zip is the tri-OS
   distribution.)
3. **Record the release** — CHANGELOG entry + a dated row in §5's ledger.

## 1a. macOS (S7g-M owner leg, on a Mac)

```bash
PYTHON=python3 bash src/harness/ops/pack_macos.sh
```

Unsigned by default this release: without the `IRONFLEET_*` env hooks the script
prints the unsigned notice and ships `IronFleet.dmg` + `.sha256`. To sign, export
the env hooks and re-run — nothing else changes.

## 2. Upgrade in place

```bash
# 1. stop every running surface (proxy, API, TUI) — Ctrl-C each
# 2. run the P0-7 backup script, note the store root
# 3. extract the new zip over the checkout / re-run the installer
bash install_linux.sh            # or: powershell -File install_windows.ps1
# 4. upgrade the stores:
harness migrate
#  Rollback = extract the previous zip, re-run its installer, `harness migrate`
#  (additive-only — migrate never rewrites history; a migrated store never needs
#  un-migrating).
# 5. prove the restore path with the new build:
.venv/bin/python scripts/restore_drill.py
# 6. verify the install:
bash verify_linux_install.sh     # or verify_windows_install.ps1 -WithDriveSmoke
```

## 3. Incident procedure

1. **A surface died unexpectedly** → read the newest log in `<store-root>/crash/`
   (version + component + traceback, local only). Fix or file the bug with that
   log attached — manually; nothing is ever sent automatically.
2. **Suspected store corruption** → do **not** open the store read-write. Run the
   drill: its SNAPSHOT phase fails loud on garbage (the sqlite_master probe), VERIFY
   reads integrity_check per DB; restore from the latest P0-7 backup if it fails.
   Never write into a corrupted store.
3. **A real restore** → the drill's phases ARE the procedure: stop surfaces, snapshot
   the current state aside, copy the backup back, verify (integrity_check + audit
   chain + row counts), then `harness migrate` on the restored root.

## 4. Supervision (Windows Task Scheduler)

No Windows service (M11 ruling ⑤): each long-running surface (proxy, API) gets a
Task Scheduler task — "run whether user is logged on", restart-on-failure every
minute, action `.venv\Scripts\harness.exe serve --routing <yaml>` (API:
`python -m harness.api serve`). The task template lives in RUNBOOK_P0_7.md's
Windows section; the API task is identical in shape.

## Appendix A — fresh-OS run sheets (owner legs)

Each sheet's evidence lands in data/eval/M11-FRESHOS/<os>/RECORD.md (templates are
generated by accept_m11.py C7). The sheets stay short because the RECORD template
asks for what matters.

### A.1 Windows

1. Fresh VM (Windows 11, BitLocker on) with the PREREQUISITES.md inventory: git,
   node, npm, Python 3.12+, Ollama + thomson1-chat / qwen3.8:27b / bge-m3.
2. Extract the zip, verify the `.sha256`, run `install_windows.ps1` — expect pin
   enforced, autoupdate:false written, store created BitLocker-gated.
3. First case: seed an operator, start Ollama, `harness drive --matter-ref <uuid>
   --task-class extraction` — one traced dispatch.
4. Restart: re-run `verify_windows_install.ps1`; surfaces return via the §4 Task
   Scheduler tasks.
5. Restore evidence: run `scripts/restore_drill.py` on the new store; keep the
   evidence block in the RECORD.

### A.2 Linux

1. Fresh VM (any distro, LUKS-encrypted home), same PREREQUISITES.md inventory.
2. Extract the zip, verify the `.sha256`, `bash install_linux.sh` — the LUKS gate
   must pass.
3. First case: `harness drive --matter-ref <uuid> --task-class extraction`.
4. Restart: `bash verify_linux_install.sh`.
5. Restore evidence: drill evidence block into the RECORD.

### A.3 macOS

1. Fresh Mac (FileVault on). `PYTHON=python3 bash src/harness/ops/pack_macos.sh`
   (unsigned by default) → `IronFleet.dmg` + `.sha256`.
2. Install from the DMG, first case via the launcher binary + `harness drive`,
   restart via the launchd agent, restore evidence = the drill on the Mac store.
